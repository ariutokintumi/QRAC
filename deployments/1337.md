## Codec proof

A plain EOA frame transaction signed (secp256k1) over **our Python-computed signature hash** was accepted by the sidecar, which returned **exactly our computed transaction hash** (`0xf96fe883…7161e`), and was mined in block 8052. That proves `tools/qrac/frametx.py` encodes transactions and signature hashes exactly like the devnet.

## QRAC frame transactions: post-quantum, zero ECDSA, the account pays its own gas

Shape: `frame 0 = VERIFY (target: account, data: validateFrameTx(), approves execution + payment)`, `frame 1 = SENDER (1,000 gwei to 0x8943…a776)`, `signatures = [ARBITRARY: 2,508-byte LMS signature]`, `nonceKeys = [frameNonceKey(epoch, one-time key)]`, `nonceSeq = 0`.

Explorer view of #5: status *On chain*; frame 0 "self-verification, payer"; frame 1 "user operation"; **"Admission report: Every rule passed"**; gossiped gateway → miner over P2P in 700 ms.

**Observation on staking:** the latest ERC-8421 draft limits unstaked entities to 100k verification gas (BUDGET-010), which our ~247k VERIFY frame exceeds. The devnet's sidecar follows an earlier draft (its `validationGasLimit` is 10,000,000) and admitted the unstaked transaction (#3). We stake anyway (#4) so the account also satisfies the rule as currently written. The decisive difference on this devnet: **canonical mempool = rejected, alternative mempool = admitted**.

## Attacks (all rejected live, `tools/devnet.py attacks`)

| Valid PQ signature, nonce key not bound to its one-time key | QRAC account | `WrongNonceKey(8, 1008)` |
| ECDSA-signed frame tx trying to drain the account (stolen or quantum-broken key) | QRAC account | `FrameSignatureNotArbitrary(1)`: no PQ signature, no approval |
